# 設計と進め方

## 形

```
design-system（CSS）                https://github.com/3pino/design-system
        │
explorer-kit（共有の部品）          packages/explorer-kit（このリポジトリのワークスペース）
  ├─ 画面     FileExplorer・FileProperties・EntryActions（小さな部品 Button・Menu・Modal などは @3pino/ui-kit-web）
  ├─ 決まり   名前・同名の扱い・移動とコピーの進め方・ゴミ箱の仮想フォルダ・並び順・フォルダごとの表示
  └─ 状態     開いているフォルダ・一覧の写し・選択・切り取り／コピーの控え・表示方法
        │                               │
   部品を使うアプリ                  fixplor
  置き場所: そのアプリのもの          置き場所: この端末（Rust）
  本体から貸す: そのアプリの機能      本体から貸す: src/lib/host.svelte.ts
```

- 共有の部品は、特定のアプリの言葉を持たない。使うアプリは、置き場所と本体の機能を渡して、自分の画面を作る。
- fixplor は、部品に「この端末」を渡し、その外側にファイラーとしての機能（ネットワークドライブなど）を足していくもの。サーバーやアカウントが無くても、ふつうのファイラーとして動く。
- 共有の部品（`packages/explorer-kit`、名前は `@3pino/explorer-kit`）は、このリポジトリの npm のワークスペース。fixplor のアプリとプラグインは、ここから直接取り込む（タグ指定の取り込みはやめた）。部品の型・試験は `npm run check`・`npm test` が、アプリの分といっしょに走らせる（CI も同じ）。

## 2 つの口

共有の部品は、次の 2 つだけを通して外とやりとりする（`packages/explorer-kit/src/types.ts`）。

1. **置き場所（`ExplorerApi`・`EntryUrls`・`Rules`・`ScopeSource`）** — 作るときに 1 つ渡す。OS や通信の違いは実装の中に閉じる。
2. **本体から借りる機能（`ExplorerHost`）** — 通知・確認・「戻る」・ファイルを開く・クリップボード・この端末の種類。

### 置き場所ごとの違いと、揃え方

| こと | サーバーの置き場所（例） | この端末（fixplor） | 揃え方 |
| --- | --- | --- | --- |
| パス | 置き場所の根からの相対（直下は空文字） | OS の絶対パス（`/a/b`・`C:\a\b`） | 部品のパスは「いちばん上からの相対・区切り `/`」に統一。この端末は `src/lib/fs/mapping.ts` で対応させる（POSIX のいちばん上は `/`、Windows はドライブの一覧） |
| ゴミ箱 | サーバーの `.trash/`（一覧・戻す・完全に消す） | OS のゴミ箱（ここからは戻せない）。WebDAV にはゴミ箱が無い | `caps.restore`（偽なら「取り消す」を出さず、確認の文も変える）。ゴミ箱が無い置き場所は `caps.trash: false` と `api.remove`（確認は「完全に削除します。元に戻せません」） |
| 特別なフォルダ | 決まったフォルダ（名前を変えられない・中にフォルダを作れない・内外の間は移動できない） | なし | `Rules.specialDir`（無ければ `null`。文は `Rules.texts`） |
| 名前の決まり | Windows でも使える名前だけ | OS の決まり（POSIX は `/` 以外ほぼ自由） | `Rules.nameError` |
| 見る（サムネイル・中身） | 認証つきの URL | Tauri の asset の URL。WebDAV は Rust の中継（`fixdav`）の URL | `EntryUrls`（`readUrl`・`thumbUrl`・`pdfSource`） |
| ファイルを押したとき | 拡大表示・ダウンロード | 写真・PDF は拡大表示（`@3pino/viewer-kit-web`）、ほかは OS の既定のアプリで開く | `ExplorerHost.viewerKind`・`download` |
| 置き場所が変わる | 接続先のサーバーを切り替える | 変わらない | `ScopeSource`（省くと、変わらない置き場所） |
| 失敗の種類 | `exists`・`parent_missing` など | 同じ名前に揃えた（Rust の `FsError.code`） | 文にするのは `ExplorerHost.errorText` |

## 決めたこと

- **ファイルの操作は Rust のコマンド（`fs_*`）だけ**。Tauri の fs プラグインは入れない（画面に渡す権限を増やさない）。
- **黙って上書きしない**。同名は `exists`。上書きを明示したときだけ、ファイルをファイルで置き換える（フォルダは置き換えない・混ぜない）。
  画面は、上書きの前に必ず確認する（共有の部品の決まり）。
- **コピー・書き込みは、宛先のフォルダの一時の名前へ書き終えてから付け替える**。失敗しても、宛先に書きかけを残さない・前の中身を壊さない。
- **完全な削除は、確認のあとだけ**。ゴミ箱のある置き場所（この端末）は、これまでどおりゴミ箱へ送る（ゴミ箱へ送るだけのときは確認を出さない。取り消せるときは、終わりの知らせに「取り消す」が付く）。ゴミ箱へ入れられないとき、黙って完全削除へ切り替えない（失敗として知らせる）。利用者が「完全に削除」（Shift+Delete）を選んだときだけ、デスクトップも確認のあとで Rust `fs_remove` が中身ごと消す（ドライブのいちばん上は消さない・リンクはリンクだけ）。
  ゴミ箱の無い置き場所（WebDAV）は `caps.trash` を偽にして、削除の前に「N 件を完全に削除しますか／完全に削除します。元に戻せません」を必ず出す（1 件でも）。「消すのはゴミ箱だけ」という以前の決めは取りやめた（Rust のローカルの動きは変えていない）。
- **ネットワークの置き場所の上書きは ETag で守る**。作成は `If-None-Match: *`、上書きは一覧で読んだ ETag を `If-Match`（引用符を付ける。変わっていれば `precondition`）。ETag を返さないサーバーのファイルは、上書きできない（`exists`）。移動・コピーは `Overwrite: F`（上書きを明示したときだけ `T`）。書き込みの一時の名前は、サーバーに任せる。
- **WebDAV の操作は Rust（`reqwest`・rustls）だけ**。WebView の `fetch` は使わない（CORS がない・任意のヘッダーを付けるため）。リダイレクトは辿らない。フォルダの大きさは、1 段ずつ読む（深さ無限の PROPFIND を断るサーバーがある。読むフォルダは 500 まで）。
- **資格情報は OS のキーチェーンにだけ保管する**（`keyring`。Linux は Secret Service・Windows は資格情報マネージャー。openssl は使わない）。使えないときは `keychain`（「キーチェーンが使えません」）で止め、ファイル・設定・localStorage へは書かない。
  置き場所の覚え（localStorage）は、名前と URL だけ。キーチェーンには置き場所の id をキーに {接続先・ユーザー名・パスワード} を 1 件。
  - パスワードは画面へ返さない（返す口が無い）。直すときは、保存済みか・ユーザー名だけを知る。パスワードを変えないなら `null`（保管済みを使い続ける）。**接続先（URL）を変えるときは、保管したパスワードを引き継がず、入れ直してもらう**（別のサーバーへ渡さない）。
  - 保管した接続先と違う接続先には、資格情報を使わない（`auth`）。暗号化されていない `http://` へは送らない（保存も断る）。この端末の中の `http://`（localhost・127.0.0.1・::1）だけは許す。リダイレクトは辿らないので、別のサーバーへ転送もされない。
  - 認証が通らない（401）と、画面は「認証情報を入れ直す」の案内を出す。置き場所を直す・外すときに、保管した資格情報も更新・消す。
- **画像・PDF は Rust の中継で読む**（`fixdav://localhost/…`、Windows・Android は `http://fixdav.localhost/…`）。WebView は認証のヘッダーを付けられず、サーバーの CORS にも頼れないので、Rust が資格情報つきで取りに行く。GET・HEAD・OPTIONS だけ。Range をそのまま渡す（PDF は要る分だけ読む）。メモリに載せるのは 1 回 256 MiB まで。URL に更新日時と大きさを付けて、WebView の覚えが古くならないようにする。
  `assetProtocol` は変えない（リモートの中身を asset へ入れない）。
- **書き込みは、少しずつ流す**: `dav_put_open`（大きさ・ETag）→ `dav_put_chunk`（4 MiB ずつ）→ `dav_put_finish`（サーバーの答え）。全体をメモリに載せない。中止は `dav_cancel`。途中で送れなくなったら、本当の理由は `dav_put_finish` が返す。
- 受け取り用の一時のフォルダ（`fixplor-dav/`）は、次の起動のときに、1 日より古いものを消す。
- **証明書の指紋の固定（ピン留め）**（`src-tauri/src/webdav/pin.rs`）。自己署名・私的な認証局の証明書のサーバーは、固定しなければ `tls`（証明書を確認できません）で止まる。
  - 流れ: `tls` の案内の「証明書を確認する」→ 指紋（SHA-256。openssl の表示と同じ形）と有効期限を見せる → 管理者から聞いた指紋と同じときだけ「この証明書を信頼する」。確認は TLS の握手の途中で止める（HTTP の要求も、パスワードも送らない）。
  - 固定したら、その置き場所は、葉の証明書がその指紋と同じものだけを受け入れる（握手の署名は必ず確かめる。チェーン・名前・有効期限は見ない＝「期限切れでも、信頼したものなら通る」）。固定は、置き場所ごと・固定したときの URL にだけ効く（URL を変えたら外れる）。
  - 違う証明書が示されたら `cert_changed`（黙って受け入れない）。案内から、前と今の指紋を並べて見て信頼し直すか、解除できる。
  - 保管は設定フォルダの JSON（`dav-pins.json`）。指紋は秘密ではなく、キーチェーンの無い環境でも使えるように、資格情報（キーチェーン）とは分けた。
  - 範囲外: 中間・ルート CA の固定、証明書の更新の追従、証明書の持ち主名の表示（解析する部品を足さないため、有効期限だけ DER から読む）。
- **シンボリックリンクは辿らずに写す**。一覧では、辿った先の種類を出す（フォルダへのリンクは開ける）。
- **隠しファイルは、置き場所の側で除く**（共有の部品は、隠すという考えを持たない）。切り替えたら一覧を再読み込みする。
- 画像のサムネイルのために、asset の URL を全部のパスに許している（`tauri.conf.json` の `assetProtocol`）。ファイラーなので、読める範囲は絞っていない。

## 一覧の操作（共有の部品 `FileExplorer`）

- **右クリック（PC）**: 項目の上は、その項目を選んで（選んである項目なら選びのまま）、項目のメニュー（コピー・切り取り・ここへ貼り付け（フォルダ）・名前の変更・削除・プロパティ。ゴミ箱の項目は元へ戻す・完全削除）。空きスペースは、これまでどおりフォルダのメニュー。タッチの長押しは、選択モードに入る。
- **名前の書き換え（PC）**: 名前の文字を押すと、選びは変えずに、`DOUBLE_CLICK_MS`（300ms）待って書き換えに入る（その間にもう一度押す＝ダブルクリックなら、開く）。文字以外の部分の押しは、これまでどおり選ぶだけ。Ctrl・Shift を押しながらの押しも、選びに足す・外す。F2・メニューからも。
- **ドラッグでの複数選択**: PC は、空きスペースからだけ、マウスで四角く囲む（Ctrl・Shift で足す）。項目の上からは囲まない（項目は、押して動かすと、ドラッグで移す。紛らわしいので、始める場所で分ける）。囲んでいるあいだに一覧がスクロールしたら（端に寄せた自動のスクロール・ホイール）、囲みの始点は一覧の中の同じ場所（同じ項目の上）に残る。タッチは、項目を長押しして選んだまま指をなぞると、その範囲を選ぶ（なぞっている間は、項目のドラッグ（移動）にしない。移すときは、切り取りと貼り付け）。
  タッチで途切れないよう、選択モードに入っても、指の下の行の要素は作り直さない（消えると、ブラウザが指の操作を取り消す）。
- **作成日時**: 一覧に、作成日時を持つ項目があるときだけ、詳細に列を足し、並び替え（≡）にも出す（プロパティにも）。この端末は、Rust が `created` を返す（持たない OS・ファイルシステムは null）。持たない項目は、並び替えでいちばん古い扱い。
- **貼り付けの予告**: 下端の貼り付けのボタンに 0.4 秒乗せる（フォーカスでも）と、貼る内容を出す。貼り付けと同じ順で決める（アプリ内のコピー・切り取り → 画像 → 文字）。文字・画像は、乗せたときにクリップボードを読む（OS が許可を尋ねることがある）。
- **フォルダのサイズ**: 置き場所が `folderSize` を持つとき（この端末）、詳細の「サイズ」の列にフォルダの大きさも出す（1 つずつ順に数える。調べる項目は 5 万まで。上限で止めたら「≥」を付ける）。持たない置き場所（WebDAV）は空欄。数えた値は、開いているあいだ覚える（フォルダの更新日時が同じなら、数え直さない。再読み込み（F5）で全部捨てて数え直す。更新日時は直下の変化でしか変わらないため）。
- **ショートカット（Windows の .lnk）**: ヘッダーの属性から、リンク先がフォルダかを読み、フォルダのアイコンで見せる（`Entry.iconKind`。押したときの動きは、ふつうのファイルのまま）。
- **タブの欄へのドラッグ**: フォルダを含むドラッグ（`EXPLORER_DRAG_DIR_TYPE` の印が付く）だけを受け、色も変える。落とすと、そのフォルダを新しいタブ（見ているタブは変えない）で開く。ファイルだけのドラッグは受けない。
- **上端（header）と下端（footer）**: 上端は、部品（ID は `HEADER_ITEMS`: 戻る・進む・上へ・隠しファイル（本体が足す。`headerItem`）、パス欄、すべて選ぶ・コピー・切り取り・貼り付け・削除、検索、新しいファイル・フォルダ）を並べる。並びと「出さない」は、設定の「上端の行・右クリックのメニュー」で決める（`menuLayout.header`、`fixplor.menus`。決めていないときは、隠しファイル・新しいファイル・新しいフォルダは出さない）。右端の ≡ はいつも出す。パス欄は残りの幅を使い、部品が並びきらないときは次の行へ回す。下端は件数だけ。パス欄は入力欄の見た目で、パンくずのボタン（ドロップ先。幅に収まらないときは左（上の階層）から隠れ、左の端を薄くする。→ は縮めない）と、各パンくずの右の **▸**（押すと、その中のフォルダの一覧。Windows のエクスプローラー風。選ぶとそこへ移る。ゴミ箱の中は出さない）、パス欄の右の空き（押しても何もしないところを最低 1.5em 残す）を押す（Ctrl+L）と出る文字の入力（`pathToText`・`resolveTypedPath`。`~` はホーム（`api.home`、省くと解かない。Android は内部ストレージの根 `/storage/emulated/0`）から、`.`・`..`・`./a` は今いるフォルダから、ほかはいちばん上から）。Enter で、`api.list` で確かめてから移る。開けなければ、理由を出して続ける）。
- **同じフォルダへの貼り付け**: コピーなら、`a copy.txt`（あれば `a copy 2.txt`。`copyName`）で作り、一覧に現れたら、名前の書き換えに入る。切り取り（移動）は、何もしない。
- **戻る・進む**: フォルダの履歴は `ExplorerNav` の `history`（戻る先）と `future`（進む先。戻ったあとに別のフォルダを開くと消える）。マウスの戻る・進むのボタン（4・5 番目）も、ホットキーの 1 つ（`Mouse4`・`Mouse5`）。
- **フォルダごとの最後の選び**（`explorer.lastSelected`。アプリを閉じるまで）: そのフォルダで最後に選んだ項目を覚え、下へ入る・戻る・進むとき、そこを選び直す（上がったときは、いたフォルダが先）。
- **ゴミ箱へ移せない項目**（`api.trashable`。WSL の中など。OS のゴミ箱に入らず消えてしまう）: Delete でも、確認のうえ完全に削除する（元に戻せない）。
- **フォルダのサイズの数え方**: 4 つまで同時に数える。Rust は、一覧を読んだときの metadata をそのまま使う（Windows では項目ごとに調べ直さない）。隠しファイルの表示を切り替えただけでは、サイズを捨てない（`nav.reload(true)`）。
- **詳細の列の幅**: 見出しの右の境目をつまんで、どの列も変えられる（右へでその列が広がり、右の列はそのままずれる。ダブルクリックで既定）。名前の列は、変えるまで残りの幅を使い、変えると固定の幅になる（このとき全体の幅は列の合計で、広い画面では右に余りが出る。狭いときは横にスクロール）。種類・サイズ・日時は折り返さず、足りない分は隠れる。幅は px（`ColumnWidths`・48〜1000）で、`columnWidths`・`oncolumnwidths` で本体が保存する（`fixplor.columns`、変えた列だけ）。列の幅は、CSS の `--col-name`・`--col-kind`・`--col-size`・`--col-modified`・`--col-created`。
- **フォルダを移ったとき（PC）**: 上へ上がったときはいたフォルダ、戻る・進む・下へ入るときはそのフォルダで最後に選んだ項目、どちらも無ければ**最初の項目**を選んで、カーソル（フォーカス）を置く。空のフォルダでは何も選ばない。起動したとき・タブを切り替えたときは、選ばない。
- **カーソル（フォーカス）と選び**（PC）: フォーカスはいつも 1 つ。押した項目・矢印で移った項目・右クリックした項目がカーソルになり、枠（outline）で見せる。選んでいる項目は、塊りつぶしで見せる。Ctrl で選びから外しても、カーソルはその項目に残る。名前の書き換えを終えたとき（Enter・Esc）は、その項目（名前を変えたときは新しい名前の項目）にカーソルを戻す（戻さないと、Enter で開けなくなる）。矢印で移るときのフォーカスは `preventScroll`（ブラウザに任せると、見えていない行を画面の真ん中までスクロールする）。
- **ファイル名が収まらないとき**: 拡張子は残して、本体だけを「…」で省略する（`verylongfil….txt`。`splitExt`。拡張子が無い・10 文字より長い・フォルダは、これまでどおり末尾で省略）。
- **見出しで並べ替え**（詳細）: 列の見出しを押すと、その列で並べる（名前・種類・サイズ・更新日時・作成日時）。並べている列をもう一度押すと昇順と降順が入れ替わり、別の列は昇順から。今の並びの列にだけ、向きの矢印を付ける。種類の順は「種類」の列の文字で、同じ種類は名前の順。≡ の並び替えもそのまま。
- **戻る・上へ上がったとき**: いたフォルダを、一覧で選んでフォーカスし、見える位置へスクロールする（PC。タッチはスクロールだけ）。こちらで選んだだけのときは、「戻る」を「選びを外す」に奪われない。
- **貼り付けを待つ間**: 始めてから、できた項目が一覧に現れるまでが 0.5 秒を超えたら、カーソルを「待つ」にする。
- **クリップボードとバッファ**: コピー・切り取りは、アプリの中のバッファ（`ExplorerBuffer`）に入れる。この端末のファイル（Windows・Linux）は、**OS のクリップボードにもファイルとして書く**（エクスプローラー・Nautilus などに貼り付けられる。文字（パスの並び）は書かない）。一緒に、こちらが書いた印（文字。独自の形式 `application/x-fixplor-buffer`）を書き、バッファの `clipToken` に持つ。貼るとき、クリップボードにこの印がまだあればバッファ（切り取りを移動にできる）、無ければ（ほかでコピーし直した）そちら（OS のファイル・画像・文字）を貼る。Ctrl+V に OS のファイルが届いても、印があれば送らずバッファ。
  - Rust（`src-tauri/src/clipboard/`）のコマンド `clipboard_set_files(paths, op, token)`・`clipboard_token()`。Windows: `CF_HDROP`・`Preferred DropEffect`（コピー 1・移動 2）。Linux: GTK のクリップボードをメインのスレッドで使い、`text/uri-list`・`x-special/gnome-copied-files`（先頭行 copy / cut）・`application/x-kde-cutselection`。このアプリが持ち主でいるあいだだけ応える（終わると消える）。
  - **ファイルとしては書かない**: Android・WebDAV・プラグイン版（`host.clipboard.files` が無い）。クリップボードには何も書かず（文字も）、**コピーした時点のクリップボードの中身を読んで控える**（`clipSnapshot`。文字はその文字、画像は種類と大きさ、空は ''）。貼るときに今の中身と比べて、同じならバッファ、違えばコピーし直したのでクリップボードを貼る。ファイルとして書こうとして失敗したときも同じ。読めなかったときは空として控える。WebDAV をファイルとして OS に渡すことはしていない。
  - まだしていない: エクスプローラー等でコピーしたファイルを、ボタンや右クリックから貼る（Windows の Ctrl+V は WebView がファイルを渡すのでできる。Linux のボタンは読めない）。
- **上端の行・右クリックのメニューの編集**（設定の「上端の行・右クリックのメニュー」。`MenuSettings.svelte`。`fixplor.menus`。上端の行も、同じやり方で部品を並べ替え・出す出さない）: 項目の右クリックと空きの右クリックの、項目の並びと「出さない」を、共通の `SortableList`（ui-kit-web。disnans の「＋メニュー」と同じ部品）と `Toggle` で決める。本体は `FileExplorer` の `menuLayout` で渡し、項目は ID で呼ぶ（`explorer-kit/src/menuLayout.ts`: 項目 `copy`・`cut`・`pasteInto`・`rename`・`restore`・`delete`・`properties`・`app`（本体が足す項目: ブックマーク）／空き `upload`・`newFile`・`paste`）。出す条件（選んだ数・書けるか・貼れるか）は部品が決め、ここで決めるのは順番と「出さない」だけ。全部を出さないと、メニューは出ない（設定に警告）。決めていない項目は、既定の順で後ろに続く。≡ のメニュー・タブ・左の欄のメニューは対象外。
- **見た目のルール**（設定の「見た目のルール」。`RuleSettings.svelte`・`lib/rules.ts`・`lib/ruleStyle.ts`・`lib/ruleIcons.ts`。`fixplor.rules`）: 条件に合うファイル・フォルダに、アイコン・色・不透明度を与える。条件は、種類（フォルダ／ファイル）・名前（拡張子を含む／除く）・拡張子・パスに、「と等しい・を含む・で始まる・で終わる・正規表現」（大文字小文字は区別しない。「でない」で逆）を、すべてに合うとき（AND）当てる。ルールは上のものほど優先で、見た目の項目（アイコン・色・不透明度）ごとに、最初に当たったルールの値を使う（色は、色の指定があれば色相より優先）。アイコンは、lucide の全部（約 2000 個）と、共通の独自アイコン（アプリのロゴ `fixplor-logo`・`disnans-logo` など。ui-kit-web の `BRAND_ICONS`、起動時（`main.ts`）に `defineBrandIcons()`）。アイコンを描くのは、共通の登録簿（`@3pino/ui-kit-web/icons`、`Icon` 部品）で、保存するのは名前だけ。`lib/lucideIcons.ts` は、名前の一覧（`lucideNames.json`）と別名での絞り込みだけを持つ。部品には `{ iconName }` で渡す。以前保存したロゴの名前（`logo`・`fixplor`）も `fixplor-logo` として読める。編集のダイアログ（`IconPicker.svelte`）で、「アイコンを設定する」のチェックを入れ、横に出る今のアイコン（初めは `file`）を押して一覧を開き、名前を絞り込んで選ぶ（空白・`-` 区切り。前方一致が先。lucide の別名でも探せる: `lib/lucideAliases.json`、`scripts/gen-lucide-aliases.mjs` で作る）。編集はダイアログで、写しを直して「保存」で反映する（キャンセル・外を押すと捨てる）。条件の「調べるもの・比べ方・値」は横 1 行。色・不透明度は「設定する」のチェックとバー・入力を横 1 行に並べる（初めの値は色相 0・`#777777`）。色相は、アプリの色と同じ明るさ（`--rule-l`）の色にする。本体は `FileExplorer` の `entryStyle(e)` で渡し、部品が、詳細・アイコン表示のアイコンと名前の色・行の不透明度に使う（ゴミ箱の仮想の項目には与えない）。保存した設定が無いときは、初めからのルール（`defaultRules`: Desktop・Downloads（folder-down）・Documents・Pictures・Music（headphones）・Videos・Library（book）・Public（building）・.git・.github のアイコン、隠しファイルを薄く、フォルダ全般は folder・色相 104、ファイルの種類（AI エージェントの指示・Playwright・Markdown・Python・Docker・設定ファイル・動画・音声・アーカイブ・データベース・表計算・CSV・JSON・電子書籍。名前で決まるものを、拡張子で決まるものより前におく）、画像・PDF・そのほかのファイルのアイコン。表示はこの設定に任せる。部品は、ルールが渡されないときのために、従来のアイコンを最後の逃げとして持つ）が入る。「デフォルトに戻す」でこの状態に戻る（ポップアップで確認）。
- **設定の「依存」**（デスクトップだけ。`DependencySettings.svelte`・`lib/dependencies.ts`）: 入れておくと便利な外部のコマンド（いまは `fd`）が入っているかのチェックリスト。Rust `fs_which`（`src-tauri/src/fs/deps.rs`）が、名前の候補（`fd`・`fdfind`）を `--version` で起動して確かめる（3 秒で打ち切り。名前は英数字と `-_.` だけ）。入っていなければ、この OS 向けの入れるコマンド（コピーボタン）・配布元（GitHub）へのリンク・入っていないものをまとめて入れるコマンド（Windows は `;`、ほかは `&&` でつなぐ）。増やすときは `DEPENDENCIES` に 1 つ足す。
- **ビューの出す・出さない**（設定の「ビュー」。`lib/views.ts`・`fixplor.views`）: ビューは場所の欄（nav.places）・親フォルダ・プレビューの 3 つ。デスクトップは、トグルで出す・出さない（初めは全部出す）。Android は、右スワイプで引き出す画面を選び、選べるのは引き出せるビュー（`drawer`）= 場所の欄だけ。親フォルダとプレビューは、Android では出さない（部品だけ残してある）。ビューを足すときは、`VIEWS` に足す。
- **親フォルダのビュー**（`ParentView.svelte`。場所の欄と一覧のあいだ）: いま開いているフォルダの親の中身を、通常の一覧と同じ並び（そのフォルダの並び順設定）で全部並べる。いま開いているフォルダは、選んでいるときと同じ背景。項目を押す（Enter）と、一覧（メインのビュー）がその親フォルダを開いて、押した項目を**選んでカーソル（フォーカス）を置く**（`explorer.revealRequest` に項目のパスを立ててから `nav.open(親)`。フォルダでも中は開かない）。開くのは、一覧で行う。いちばん上では何も出さない。既定の幅 200px。
- **プレビューのビュー**（`PreviewPane.svelte`。一覧の右）: 一覧のカーソル（`FileExplorer` の `oncursor`）の項目の中身。無ければ何も出さない。フォルダは直下の一覧、画像・SVG（市松模様の上）・PDF（一覧のサムネと同じ部品）は絵で、テキストは先頭の 100 行（64KB まで。`preview.ts`）を highlight.js（`highlight.ts`。言語は、見るときに 1 つずつ読み込む。拡張子・ファイル名で決める）で色付け。文字かは先頭を見て（NUL を含む・UTF-8 として読めないものは文字ではない）決め、動画・音声・書庫などは読まない（種類・サイズ・更新日時だけ）。矢印で素早く動かしているあいだは読まない（150ms 待つ）。色は自前（暗い背景向け）。既定の幅 320px。
- **横のビューの枠**（`components/SidePane.svelte`）: 一覧との境目に、幅を変えるつまみ（ドラッグ・左右の矢印・Home。`fixplor.parentsWidth`・`fixplor.previewWidth` に保存）。窓が狭いときは、横のビューが（下限 120px まで）縮み、一覧は 300px を残す。隠しはしない。
- **上端の行は必ず 1 行**: パス欄は最小幅（9em）まで縮め、それでも入らない部品は、右から順に隠す（`fitBar`。次の行へ回った部品を `data-clipped` で隠す。隠したぶんは、どこにも出さない）。≡ はいつも出る。「並び替え」のボタン（`sort`）もあり、≡ の中の「並び替え」と同じメニューを開く。
- **SVG**: 画像として扱う（`<img>` で描く。スクリプトは動かず、currentColor は黒）。透けるので、サムネイル・プレビューとも、白と灰色の市松模様を敷く。
- **左の欄（ブックマークとドライブ）**（`PlacesNav.svelte`・`lib/bookmarks.svelte.ts`）: 上から「ブックマーク」「ドライブ」。ブックマークには、見た目のルールどおりのアイコン・色を付ける（一覧のフォルダと同じ。ルールが無ければ folder。ドライブには付けない）。ブックマークは、置き場所の id とフォルダの組（`fixplor.bookmarks`。各デバイスに保存）。初めて開いたときだけ、この端末のよく使うフォルダを入れ、そのあとは利用者が決める。追加は、見出しの「＋」（いま開いているフォルダ）・一覧のフォルダの右クリック（`FileExplorer` の `entryMenu`）・欄へのドラッグ。削除は、項目の右クリック。並べ替えは、ドラッグ（HTML5 の DnD）・右クリックの「上へ移動」「下へ移動」（タッチはこれ）・ホットキー（`bookmark.moveUp`・`bookmark.moveDown`。既定はなし。フォーカス中のブックマーク、無ければいま開いているフォルダのブックマークを動かす）。動きは、タブと同じ（動かしている行が空け、ほかの行がずれ、落とすと滑って収まる。席は、ずらす前のレイアウトの位置で決める）。末尾に点線の空き（「フォルダをここへドロップして追加」。フォルダをドラッグして左の欄の上に持ってきたときだけ出す）が出て、フォルダを落とすと足せる。一覧の項目をブックマークの上へ落とすと、そのフォルダへ移る（Ctrl でコピー。見ている置き場所のブックマークだけ。`explorer.dropDragged`）。ブックマークの名前は、フォルダの名前そのまま（ホームはユーザー名）。ネットワークの場所を外すと、その場所のものも外す。ホットキーで「n 番目を開く」（1〜9）と「ブックマークから検索」（`BookmarkSearch.svelte`。名前・場所で絞り、Enter で開く・Ctrl+Enter で新しいタブ）を付けられる（既定のキーは無し）。ドライブの節は、この端末のドライブ（Windows の WSL を含む）・SD カード・ネットワークの場所。項目の右クリックは、新しいタブ・新しいウィンドウ・ブックマークから削除・直す。設定のタブでは、左の欄を出さない。
- **WSL（Windows）**: `wsl.exe -l -q` で入れてあるディストリビューションを読み（`places.rs` の `wsl_distros`。2 秒で諦める）、`\\wsl$\<名前>\` を、ネットワークの場所（UNC）と同じ形でドライブに並べる。全ドライブの検索には入れない。
- **場所の欄（Android の狭い画面）**: 幅が 767px 以下の Android では、左から出す引き出しにする（デスクトップは、どんなに狭くても、場所の欄はいつも見える）。右へスワイプ（縦より横が大きく、56px 以上）で出し、左へのスワイプ・暗くした外側を押す・「戻る」・場所や「設定」の行を押す、のどれでも閉じる。開いているあいだは、これがいちばん上で、残りは暗くする。バージョンの行（about-row。歯車つき。押すと「設定」のタブ）も、この中に入っている。横にスクロールしている一覧の上・入力欄・ダイアログ・メニューの上・一覧の長押しからのなぞりでは、スワイプにしない。広い画面は、これまでどおり左に固定（つまみで幅を変えられる）。

## タブ・検索（段階 6）

2 画面（左右に並べる）は、やらない（利用者の判断）。

### タブ（アプリだけ）

- **タブ = 置き場所 + フォルダ**。タブごとに、エクスプローラーを 1 つ持つ（フォルダ・戻る履歴・選び・表示・検索の文字）。タブを切り替えても、それぞれのまま。
  タブの中で左の場所を押して置き場所を切り替えても、その置き場所で開いていたフォルダ・選びは、そのタブの中で保つ（以前と同じ）。
- **置き場所ごとに共有するもの**: この端末の置き場所・ネットワークの置き場所の接続（読んだ ETag を含む）と、切り取り・コピーのバッファ（共有の部品の `createExplorer({ buffer })`）。
  同じ置き場所のタブのあいだは、コピーして別のタブへ貼り付けられる。別の置き場所とは共有しない（パスが別の置き場所のものになる）。
- **置き場所**: 画面のいちばん上に、タブの欄（`components/TabBar.svelte`）。決まり（保存・復元・並べ替え・閉じたあとの選び方・名前）は `lib/tabs.ts`（画面に依らない）。
- 操作: 押して切り替え・＋（いまの置き場所のいちばん上。この端末はホーム）・× と真ん中のボタンで閉じる・右クリックのメニュー（複製・左右へ移す・閉じる・ほかを閉じる）・ドラッグで並べ替え。
  フォルダを一覧からタブの欄へドラッグすると、落とす前に、新しいタブができる位置に点線のタブ（フォルダの名前つき）を見せる（タブの左半分の上なら前、右半分なら後ろ、タブの無いところならいちばん後ろ）。落とすと、そこに新しいタブを作る（見ているタブは変えない）。ドラッグ中の項目は、DataTransfer が落とすまで読めないので、`explorerDragItems()`（部品がドラッグの間だけ覚える）から名前を取る。
  タブの並べ替えは、動かしている間、ほかのタブが空きの分だけずれ、落とすと滑って収まる（FLIP）。タブを足す・閉じる・移すときも、残りのタブは滑る。
  タブは、全部同じ表示（狭い画面でも、一覧に切り替えない）。多いときは、欄の中を横にスクロールする（バーは出さず、縦のホイールも横に動かす）。続きがある側の端に影を出す。
  × は、最後の 1 つにも出す。最後の 1 つを閉じる（× か Ctrl+W）と、ウィンドウを閉じる（Android は、アプリを終える。`exit_app`）。別のウィンドウのときは、そのウィンドウだけ。
  **デスクトップは、タブの欄がタイトルバーを兼ねる**（`decorations: false`）。左端にアイコン・右端に最小化・最大化・閉じる（`WindowControls.svelte`）・タブのあいだの空きは、ウィンドウを動かす（`data-tauri-drag-region`。ダブルクリックで最大化）。権限は `capabilities/desktop.json`。
  **タブをウィンドウの外までドラッグして離すと、別のウィンドウで開く**（デスクトップ）。`dragend` で、どこにも落ちず（dropEffect が none）、位置がウィンドウの外のとき。新しいウィンドウは `index.html?place=…&dir=…` で開き、そのタブ 1 つで始める（タブの保存は、元のウィンドウのものを上書きしない）。1 つだけのタブは動かさない。実際の WebView（WebView2・WebKitGTK）での、離した位置の値は未確認。
  **ホットキーは、設定で変えられる**（画面は土台 `@3pino/app-kit-web/settings/HotkeySettings.svelte`。`components/HotkeySettings.svelte` は、操作の一覧と保存を渡すだけ。設定の「操作」→「ホットキー」の画面）。操作ごとに、キーを複数持て、足す（「＋」を押してキーを押して記録。Esc も記録できる。もう一度「＋」を押す・フォーカスが外れると、記録をやめる。マウスの戻る・進むのボタンも記録できる）・外す・既定に戻す。節（アプリ・タブ・移動…）は、見出しを押して開く・折りたたむ（初めは折りたたみ）。ホットキーの画面を開いているあいだの「戻る」は、設定のいちばん上へ戻る。**連続して押すキー**（`G G`）も、記録できる（「＋」でダイアログが開き、押したキーが順に並ぶ。「記録終了」ボタン（Enter の長押し）で確定、「キャンセル」（Esc の長押し）でやめる（長押しの間は、対応するボタンが左から徐々に明るくなる）。押しっぱなしの繰り返しは足さない。照合は 1 秒以内。表示は `G → G`。既定ではどこにも割り当てない）。`H` と `G H` を両方付けたときは、G のあとの H は `G H` が先に当たる（土台に、連続のキーを登録して実現: `registerHotkeySequences`。設定が変わるたびに `lib/hotkeys.svelte.ts` が渡し直す）。Shift を押しながらの矢印（選びに足す）も、操作（「上の項目へフォーカスして両方選択」など `extendUp`…`extendRight`。既定 Shift+矢印）として、設定で変えられる。一覧の上に、操作の名前・キーで絞る検索欄。操作に「最初・最後の項目を選択」（Home・End）・「パス入力欄にフォーカス」・「ほかのタブを閉じる」「タブを左へ／右へ移す」・「フォルダを新しいタブで開いて移る」（Ctrl+Enter）・「開く（今のタブに残る）」（既定なし）・ブックマークの操作を足した。ほかの操作と同じキーを足すと、警告を出す（止めはしない）。変えた操作だけを `fixplor.hotkeys` に保存する（既定が変わったとき、変えていない操作は追従する）。
  操作の一覧・既定・保存の決まりは `lib/hotkeys.ts`（画面に依らない。節: アプリ・タブ・移動・ブックマーク・選択・編集・表示）と `lib/hotkeys.svelte.ts`。キーの文字（`Ctrl+Shift+Tab`。英数字はキーの位置で決める）と、上書き・重なりの決まりは、土台 `@3pino/app-kit-web` の `core/hotkeys`・`core/hotkeyBook`（共有の部品 `hotkeys.ts` は、一覧の操作の既定 `EXPLORER_HOTKEYS` を持ち、照合の関数はそこから出し直す）。**アプリ側が受ける操作**（タブ・設定・完全終了・戻る・上の階層・再読み込み・隠しファイル・パスをコピー・フォルダを新しいタブ／ウィンドウで開く）は `App.svelte` の `runCommand`。**一覧の操作**（検索・開く・名前の変更・選びを外す・上下左右の項目・すべて選ぶ・コピー・切り取り・貼り付け・ゴミ箱・完全削除・新しいファイル・表示・元に戻す・やり直し）は、`FileExplorer` の `keymap` で渡す（省けば既定）。
  文字を打っている入力欄の中では、修飾キー（Ctrl・Alt）のないホットキーは働かない。矢印の移動は、Shift を押していても同じキーとして扱い（Shift なら、選びに足す）、Ctrl・Alt を押していれば別のキー（Ctrl+↑ は「上の階層へ」）。Alt+F4 は、OS が先に受けて、このアプリには届かないことがある。
  **元に戻す・やり直し**（`history.ts`。アプリで 1 つ・100 件まで・アプリを閉じると消える）: 名前の変更・移動・コピー・新しいファイル（フォルダ）・ゴミ箱へ移す。上書きしたもの・完全な削除・アップロードは積まない。コピー・新しいファイルを戻すときは、できたものをゴミ箱へ入れる（ゴミ箱から戻せる置き場所だけ積む）。デスクトップの OS のゴミ箱（Windows・Linux）は、入れたときに項目の id を控え（Rust `fs_trash` が返す。`trash::os_limited`）、`fs_os_trash_restore` で元の場所へ戻す（元に同じ名前があれば、戻さない）。id を見つけられなかったものは、戻せないので積まない（「取り消す」も出さない）。
  **キーボードで項目を移る**（PC）: 矢印で、フォーカスと選びが一緒に移る。アイコン表示は、列の数（CSS の `grid-template-columns`）だけ上下に動く。フォーカスのある行は、`:focus-visible` の枠で見せる（PC のファイルの行 `<a>` にも `tabindex` を付けた）。
  **設定**はタブの 1 つ（左下の「fixplor v…」の行から開く。1 つだけ。保存・復元もされる）。中身は「ホットキー」と「バージョン」（版と、アップデートの確認・入れ替え）。設定のタブを見ているあいだは、左の欄を出さない（Android のスワイプでも、引き出しも暗い幕も出しない）。設定の画面は、他のタブを見ているあいだも作ったままにし、戻ったときに、ホットキーの画面・開いた節・検索の文字が続きから見える。
  キー: Ctrl+T 新しいタブ・Ctrl+W 閉じる（最後の 1 つなら、ウィンドウを閉じる）・Ctrl+Tab / Ctrl+Shift+Tab / Ctrl+PageDown / PageUp 切り替え・Ctrl+1〜9 番号（9 は最後）。
- **上限**: 20 個（超えたら知らせて作らない）。最後の 1 つは閉じない。
- **保存・復元**: `fixplor.tabs`（`localKeys.ts` に登録）に、置き場所とフォルダと見ているタブだけを保存して、起動で戻す（外した置き場所のタブは捨てる・壊れた値は 1 つのタブで始める）。
  選び・表示・戻る履歴は保存しない。ネットワークの場所のタブは、見るまでつながない。
- **Disnans のプラグインには、タブを入れない**。プラグインは本体のパネルの 1 つの view で、本体の画面の切り替え（ナビバー・戻る）に収まる。タブの欄が上端の安全域・本体の戻る操作とぶつかり、小さい画面で場所を食うので、見送った。

### 検索（共有の部品 + 置き場所）

- **画面**（共有の部品 `FileExplorer`）: バーの虫めがね・Ctrl+F で、パンくずの下に検索の欄が開く（Esc・×・戻る（Android の戻る）で閉じる）。2 つの使い方:
  1. **名前の絞り込み**（どの置き場所でも）: 入力した文字を名前に含む項目だけ、いま開いているフォルダの一覧に残す（大文字小文字は区別しない）。置き場所には頼まない。
  2. **サブフォルダも**（置き場所が `search` を持つときだけ、チェックを出す。検索を開くと、入った状態から始まる）: 開いているフォルダの下を、浅いフォルダから探す。一覧が**結果の一覧**（名前・見つけた場所）に替わり、件数・探している印・途中で止めた理由を欄に出す。
     結果は、押すと開く（フォルダは中へ・画像と PDF は拡大表示・ほかは保存）。虫めがねのボタン（場所を開く）で、そのフォルダへ移って項目を選ぶ。
     文字・チェック・フォルダが変わるたび、前の検索は中止して、250 ms 待ってから新しく始める。
- **口**（`ExplorerApi.search?`・任意）: `search(query: { dir, text }, { hits(entries), signal }) → { partial }`。見つけたものは `hits` で少しずつ渡す。`signal` が中止されたら、速やかに止めて reject（code `aborted`）。
  上限は置き場所が決め、止めたときは `partial` に理由（`hits` 件数／`scan` 調べた数／`depth` 深さ／`time` 時間。null は最後まで調べた）を返す。黙って打ち切らない。
  画面も、表示する件数を `SEARCH_MAX_HITS`（1000）で止める。
- **この端末**（Rust `fs_search`・`src-tauri/src/fs/search.rs`）: 外部の `fd`（fd-find。`fd`・`fdfind`）が入っていれば、それで探す（`--fixed-strings --ignore-case --no-ignore`。隠し項目は「隠しファイルを表示」だけ、上限の件数・深さ・時間は fd に渡すか自分で見る。並びは fd の順）。無い・うまく動かない（何も返さずに失敗）とき、および Android は、自前で探す（`search_builtin`）。自前の探し方は、幅優先で歩き、見つけた項目を 50 件ずつ Tauri の Channel で流す（途中から並ぶ）。`fs_search_cancel(job)` で止める。
  上限: 1000 件・調べた項目 30 万・深さ 64・60 秒。シンボリックリンクのフォルダは辿らない（名前が当たれば項目としては出す）。隠し項目は、「隠しファイルを表示」が切れていれば、出さず・中へも入らない。読めないフォルダは飛ばして続ける。
  Windows のいちばん上からは、ドライブを 1 つずつ探す。
- **ネットワークの場所（WebDAV）**: サーバー側の検索は一般には無い（`SEARCH` は標準ではない）ので、手元で、浅いフォルダから `PROPFIND` を 1 つずつ（`lib/fs/search.ts`）。サーバーに負担なので、上限は小さい: 読むフォルダ 80・深さ 8・1000 件・60 秒。
  上限で止めたときは、結果の欄に「途中までです」と理由を出す。下のフォルダが読めなければ飛ばす（検索を始めたフォルダが読めなければ失敗）。
- **Disnans のプラグイン**: `search` は渡さない（Disnans にはメッセージの検索が別にある。共有フォルダの再帰は、本体の API が無い）。名前の絞り込みだけが使える。

## これから（段階 7）

機能:

- OS からのドロップ（ほかのアプリからファイルを落とす）と、OS のクリップボードのファイルの貼り付け
- 長いコピー・移動（ネットワークの場所の送信の進み具合と中止は済み）、フォルダの見張り（ほかのアプリの変更を、再読み込みせずに映す）
- OS のゴミ箱の中身を見る・戻す（デスクトップ。Android はアプリの中のゴミ箱で、画面から戻せる）

足りないところ:

- 外枠（タブの欄・左の場所の一覧）の見た目は仮。利用者の確認を取っていない。
- Windows・Linux・Android は、実機で一通り確かめた。
- UTF-8 でない名前のファイルは、一覧には出るが操作できない。
- 移動は「同名が無いことを確かめてから付け替える」ので、そのあいだに別のアプリが同名を作ると上書きになる（Linux では `renameat2` で防げる）。
- CSP は未設定（`null`）。外の内容は読まないので、あとで締める。
- サムネイルは、縮小版を作らず画像そのものを読む（大きい画像の多いフォルダは重い）。プレビューのテキストは、先頭 64KB だけ読んで打ち切る。
- 小さな部品（Button・Menu・Modal など）は、共有パッケージ @3pino/ui-kit-web のもの（explorer-kit・fixplor が同じものを使う。写しは無い）。

## SD カード（Android の別の置き場所）

差した SD カード（`/storage/<uuid>`）は、内部ストレージとは別の置き場所（タブ・左の欄の 1 つ）として出す。根はそのカードだけで、いちばん上の一覧にも内部ストレージの中にも混ぜない（だから、内部ストレージの `.fixplor-trash` とは関係がない）。
カードにはゴミ箱を作らない（隠れたゴミ箱を残さない）ので、`caps.trash` は偽、削除は確認の文（「完全に削除します。元に戻せません」）のうえで `fs_remove` で消す。カードが外れていれば、その欄は出さない（一覧の取り直しで消える）。
SD の置き場所は、タブの保存・復元の対象にしない（次に起動したとき、そのタブは捨てられる）。

## Android の許可とアイコン

- **ファイルの許可**: Android 11 以上は「すべてのファイルへのアクセス」（`MANAGE_EXTERNAL_STORAGE`。アプリの情報の「権限」の欄には出ず、特別なアクセスの設定画面で与える）。「許可する」で、このアプリの設定画面（`ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION`）を開く。Android 10 以下は、ふつうの保存領域の許可（`READ/WRITE_EXTERNAL_STORAGE`。最初の 1 回はシステムのダイアログ、拒否したあとはアプリの情報）。
  許可が無いあいだは、一覧の上に案内（「許可する」）を出し続ける。アプリに戻ったとき（focus）に確かめ直し、許可されていれば案内を消して一覧を再読み込みする。
  GrapheneOS では、設定画面の前に「Allow fixplor access to manage all files?」の確認が出る。ほかのアプリの窓が画面に重なっている（例: Tasker のオーバーレイ）と、この確認のボタンが押せない（OS がタッチを捨てる）。アプリの側では直せないので、重なっている窓を消す。
  センサー（`OTHER_SENSORS`）は、アプリが求めているのではなく、Android 17 が全アプリに付けるもの（APK の `uses-permission` には無い。INTERNET・MANAGE_EXTERNAL_STORAGE・REQUEST_INSTALL_PACKAGES と、Android 10 以下の保存領域だけ）。
- **アイコン**: 元は `icon.svg`。`src-tauri/icons/app-icon*.svg`（色は、アプリの暗い配色の背景・アクセントを、色相 104 で hex にしたもの）から、PNG を作って（Inkscape）、`npm run tauri:icon` で各 OS の分を作る。`gen/android` があれば、Android の分は `gen/android` へ直接書かれる。
